# بصيرة — موسوعة فقهية مع مساعد مُسنَد بالمراجع

نسخة أولية عربية RTL متجاوبة مع الهاتف والكمبيوتر، قابلة للنشر مباشرة على GitHub Pages **دون بناء أو تثبيت Node**.

## حالة المحتوى الحالية

- **24 بابًا** من أبواب الفقه والمعرفة الإسلامية.
- **253 عنوان مسألة** في فهرس البحث.
- **31 مسألة لها ملخصات تمهيدية مع إحالات لمصادر محددة**؛ باقي العناوين فهرس فقط ولا يُنشَر فيها حكم شرعي غير موثق.
- **27 مرجعًا محددًا** بين آيات وأحاديث ومواضع من كتب علماء وقرارات مجامع فقهية. تكرار المصدر بين المسائل وارد.
- أقوال منسوبة إلى ابن القيم مع مواضعها في «إعلام الموقعين» و«زاد المعاد» وروابط أصلية للتثبت. نصوص العلماء لا ينبغي التعامل معها كفتوى مباشرة في كل واقعة.
- جميع النصوص التعليمية مختصرة، وليست مراجعة علمية مؤسسية أو فتوى شخصية.

## رفع النسخة إلى GitHub Pages

1. أنشئ مستودعًا جديدًا باسم مثل `basira`.
2. **ارفع محتويات ZIP مباشرة إلى جذر المستودع**؛ يجب أن يظهر `index.html` في المستوى الأعلى، وبجانبه `data`.
3. من GitHub ادخل Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/ (root)` ثم Save.
4. رابط الموقع سيكون على الشكل: `https://USERNAME.github.io/basira/`.
5. فور نشر الملفات يعمل البحث والتصفح والمفضلة والوضع الداكن والمساعد **المحلي المستند للمراجع** دون اشتراك أو API.

> لا تستخدم فتح `index.html` مباشرة من قرص الحاسوب (`file://`) لاختبار جلب ملفات JSON؛ استخدم GitHub Pages أو خادم HTTP محلي: `python -m http.server 8000`.

## تشغيل دردشة ذكاء اصطناعي حقيقية (اختياري)

**بدون هذه الخطوة الدردشة عبارة عن بحث تفاعلي في قاعدة المعرفة، وليست نموذج توليد لغوي.**

1. جهّز حساب Cloudflare Workers وحساب OpenAI API مؤهلًا ومزودًا برصيد خدمة API. اشتراك ChatGPT وحده لا يوفّر مفتاح API.
2. ثبّت أداة Cloudflare Wrangler واستعمل `npx wrangler login`.
3. في `wrangler.toml` غيّر `ALLOWED_ORIGIN` إلى أصل صفحتك تمامًا، مثل `https://USERNAME.github.io` **بدون** `/basira/`؛ لأن المتصفح يرسل أصل النطاق فقط. هذا الأصل هو نفسه حتى إن كان لديك أكثر من مستودع GitHub Pages.
4. شغّل `npx wrangler secret put OPENAI_API_KEY` وأدخل المفتاح في أداة Cloudflare الآمنة، لا في المستودع أو `config.js`.
5. شغّل `npx wrangler deploy` من مجلد المشروع لتشغيل ملف `worker.js`. سيستورد ملفي `data/topics.json` و`data/evidence.json` مع الخادم.
6. انسخ عنوان الـWorker المنشور، مثل `https://your-worker.workers.dev`، إلى `config.js` في `API_BASE_URL`، ثم أعد نشر الملف على GitHub Pages.
7. اختبر سؤالًا له مستندات في الموسوعة. إذا غاب المفتاح أو تعطلت الخدمة، يعرض الموقع إجابات البحث المحلي بدلًا من الادعاء بوجود ذكاء اصطناعي يعمل.

**مهم للأمان والتكلفة**: هناك حد أولي مؤقت للطلبات في Worker لكنه غير موزع بين كل الخوادم. قبل استقبال زوار كثيرين، فعّل Cloudflare Rate Limiting/Turnstile، وحدود إنفاق API، والمراقبة، ولا تفتح الوصول لمفتاحك من المتصفح. الـAI قد يخطئ في الفهم والنقل حتى مع وجود المصادر؛ اعتمد سياسة مراجعة بشرية للإجابات الحساسة.

## قاعدة المعرفة وتوثيق الأقوال

- `data/categories.json`: الأبواب ومعلوماتها.
- `data/topics.json`: العناوين والتصنيف وحالة النشر (`index` فهرس، `intro` ملخص موثق).
- `data/evidence.json`:
  - `sources`: مراجع مستقلة، لكل مصدر نوع (`quran` أو `hadith` أو `scholar` أو `council`) والقائل والكتاب أو رقم الحديث والاقتباس ورابط الصفحة.
  - `entries`: مسألة برقم `F...` تحتوي ملخصًا تمهيديًا، ومعرّفات مراجع `sourceIds`، وتنبيهًا خاصًا.

لا تضف حالة `intro` لموضوع **إلا** بعد إدخال `entries[ID]` يحيل إلى مصدر حقيقي. انسب النص حرفيًا لقائله فقط إذا تحققت من الطبعة والموضع؛ وإلا قل «ذكر بمعناه» أو «يُستفاد». عند الاختلاف الفقهي اذكر الأقوال ومذاهبها وأدلتها ومواضع النزاع بدل تسوية الخلاف بالذكاء الاصطناعي. يجب إضافة هيئة مراجعة علمية قبل الترويج للموقع باعتباره موسوعة فتاوى شاملة.

## الإضافات المطلوبة للوصول إلى مشروع موسوعي شامل

- تحرير بقية 222 عنوانًا بإحالات نوعية محددة، لا روابط عامة.
- فهرسة مذهب المالكية وبقية المذاهب بطريقة لا توهم الاتفاق؛ إنشاء محرر نصوص ولوحة تحكم مع تاريخ المراجعات وهوية المراجع العلمي.
- إضافة محرك RAG يعتمد مقتطفات من كتب ذات حقوق استخدام واضحة، مع فهرسة مواضع الطبعات والصفحات؛ التحقق الآلي من الإحالة مع تدقيق بشري للجواب.
- إنشاء خدمة سؤال مفتي أو إحالة إلى مؤسسات فتوى رسمية للحالات الشخصية.
- استكمال بيانات المشغل والخصوصية وإشعارات معالجة الأسئلة قبل الإطلاق التجاري.

## اختبار المحتوى

من مجلد المشروع (عند توفر Node وPython):

```bash
node --check app.js
node --check worker.js
python validate_content.py
```

راجع دائمًا المصدر المباشر وصفحته في المسائل التي تُضاف. روابط خارجية قد تتغير بمرور الوقت.
